# 进攻分时雷达 · Attack Radar

> 面向 **A股日内强势股** 的实时筛选 + 每日自动复盘迭代系统。
> 盘中每 2~5 分钟扫描一次候选池，用**概率模型**给每只票估计"涨停概率"并推送报警；收盘后**自动复盘当日真实结果**（命中率/涨停率/浮盈/回撤），并据此**自动迭代模型权重**，形成持续优化闭环。

> ⚠️ 本项目是个人量化研究工具，仅供学习研究，不构成任何投资建议。股市有风险。

## 它解决什么问题

传统"涨停池监控"只告诉你"谁涨停了"（滞后），本项目要做的是：

1. **盘中**就判断出"哪些票**有潜力**封板"——不是事后，是**事前**；
2. 给出的不是模糊的"强势"，而是**可验证的涨停概率**；
3. 每天收盘后**自动核对**昨天预测得对不对，**自动调参**，让系统越用越准。

核心思想：把"选股"从一次性的人工经验，变成一个**可持续学习、可量化验证**的闭环系统。

## 系统架构（四层闭环）

```
盘中（每2-5分钟一轮）                     盘后（15:05后自动，每日一次）
┌─────────────────────────────┐         ┌──────────────────────────────┐
│ 候选池                       │         │ review.js 收盘复盘            │
│  涨停池+炸板池 + 成交额榜前80 │         │  拉全天分时 → 算真实结果       │
│        ↓                    │         │  命中率/涨停率/浮盈/回撤/      │
│ 过滤（排ST/科创/一字/已封死） │         │  校准误差/误判/漏报           │
│        ↓                    │         │        ↓                     │
│ score.js 规则引擎(形态分)     │         │ iterate.js 参数迭代           │
│        ↓                    │         │  打标签→SGD更新权重→           │
│ features.js 21维特征向量     │  样本落盘│  分箱校准概率→阈值寻优         │
│        ↓                    │  ────▶  │        ↓                     │
│ model.js logistic概率估计    │         │ model_state.json 版本+1       │
│        ↓                    │         │ （次日盘中即用新权重）          │
│ 候选榜Top10 + 双确认报警      │         └──────────────────────────────┘
└─────────────────────────────┘
```

| 文件 | 职责 |
|---|---|
| `server.js` | 主服务：扫描循环、候选池、评分、样本落盘、候选榜、盘后自动复盘调度、HTTP 接口、买点观察态推进 |
| `score.js` | 规则引擎：高开/洗盘/防守/收复/低点抬高/量结构 + 量价配合奖励分（0~100+） |
| `buypoint.js` | 两阶段买点状态机：20cm纪律资格审查 + 低位直取/延续确认门双档买点判定 |
| `features.js` | 特征工程：21 维特征 + z-score 标准化 + 人类可读信号 |
| `model.js` | 概率模型：logistic 回归 + 在线 SGD + 分箱校准 + 阈值寻优 + 版本化状态 |
| `review.js` | 收盘复盘：真实结果统计 + 误判/漏报案例 + HTML 报告 |
| `iterate.js` | 参数迭代：标签化 → 权重再训练 → 校准 → 阈值寻优 → 特征漂移监测 |
| `radar.html` | 盘中看板（候选榜/报警时间线/买点信号卡片/操作按钮栏） |

## 数学建模方法

刻意**不用简单加权加分**，而是引入可验证的概率与学习框架：

### 1. 概率估计（替代打分）
规则分只是序数信息（90 > 80，但差 10 分意味着什么？）。模型输出 **P(当日达到涨停/大涨)**，可直接回答"这票有几成把握"。

```
P = σ(β₀ + Σ βᵢ·zᵢ)，   zᵢ = (xᵢ - μᵢ)/σᵢ  （截断 ±4）
```

βᵢ 不是拍脑袋的固定权重，而是**从每日真实结果中学出来的**。

### 2. 特征（21 维，7 组）
- **竞价形态**：高开幅度、洗盘深度、洗盘量能、收复速度、低点抬高
- **量能结构**：量结构分、量价配合分、放量脉冲次数
- **时序动量**：涨速(%/分)、涨速加速度
- **波动**：日内振幅
- **流动性**：换手率、成交额分位
- **盘口博弈**：连板数、炸板次数(负)、封单/流通市值
- **市场与板块**：板块涨幅、板块名次、板块涨停家数、市场热度

### 3. 在线学习（自适应权重）
每个交易日收盘后：
- **标签**：收盘封板/盘中摸板 → y=1；收涨≥5% → y=0.7；其余 → y=0
- **SGD 随机梯度下降**：最小化交叉熵 + L2 正则（防过拟合），学习率随样本量衰减
- **样本池滚动**：保留最近约 600 个样本，防止远古行情拖累新风格
- **冷启动保护**：累积样本 < 15 只记录不更新，避免拿小样本瞎调参

### 4. 概率校准
SGD 输出的概率天然有偏，用**分箱保序校准**把它映射到真实命中率；复盘报告里的 **Brier 分数**持续监控校准质量。**置信度 = 概率 × 模型成熟度**，冷启动期自动压低置信度。

### 5. 阈值寻优（最优报警线）
在累积样本上网格搜索报警阈值：`目标 = 命中率 - 0.02 × max(0, 报警数-8)`（命中率优先，报太多要罚）。每日复盘后自动更新，次日生效。

### 6. 双确认报警
**规则分 ≥ 80 且 概率 ≥ 阈值** 才报警——规则分管"形态像不像"，概率管"成色够不够"，两个都过才响，降低单一维度误报。

### 7. 两阶段买点状态机（`buypoint.js`）
**报警 ≠ 买点**。报警触发的是日内高点概率大（形态最漂亮的时刻往往就是价格被推高的位置），直接追报警价 = 结构性追高。因此把"发现"和"介入"拆成两阶段：

**介入资格审查（报警触发时）**
- 只做 **20cm（创业板）**，10cm/科创板不进观察
- 报警时涨幅 **≥ +5%** 不进观察（晚了没博弈价值）
- 报警时 **< +3.5%** → **低位直取**：报警即买点（确认门在此档是累赘）
- 报警时 **+3.5~5%** → 进入**延续确认门**

**延续确认门（观察态逐分钟推进）**
1. 报警后必须**突破报警价 +0.6%**（确认延续）才解锁买入资格
2. 确认后在**缩量微回踩 / 深回踩放量企稳**处给出买点
3. 报警后 **45 分钟不创新高 = 派发顶**，永久放弃
4. 任意时刻跌破报警价 **-4% 防线**，放弃

**回测验证**（34只20cm候选 × 2交易日 = 68票·日样本，26次报警）：
- 管线成交 11 笔：平均 **+1.65%**，胜率 **8/11（73%）**
- 对照"报警价直接买" 26 笔：平均 +1.18%，胜率 ~50%
- 被过滤器拦下的 13 笔若直接买：4盈9亏（亏损率 69%）
- 锚点样本：天山生物（8/24 +20% 涨停日）低位直取 +16.6%；当日 4 只套人票全部正确拦下
- 因子验证：报警后 30 分钟创新高 → 胜率 13/16；不创新高 → 胜率 1/10（确认门的核心依据）

## 快速开始

### 环境要求
- **Node.js 18+**（项目零第三方依赖，纯标准库 + 原生 `fetch`）
- 可访问 A 股公开行情接口（数据源为公开接口，见下）

### 运行
```bash
node server.js
```
服务启动后默认监听 **8732** 端口，浏览器打开看板：

```
http://localhost:8732
```

### 自动调度（无需干预）
- **交易日 9:25–11:35 / 12:55–15:05**：自动每 2~5 分钟扫描一轮
- **交易日 15:05–16:30**：自动跑收盘复盘 + 模型迭代（每日仅一次）
- **非交易时段**：零请求休眠，自动算好下次开盘时间

### HTTP 接口
| 接口 | 说明 |
|---|---|
| `GET /` | 盘中看板（radar.html） |
| `GET /api/data` | 全量快照（候选榜/报警/模型状态，JSON） |
| `GET /api/scan` | 手动强扫一轮（非交易时段会拦截） |
| `GET /api/review` | 手动触发复盘 + 迭代 |
| `GET /api/report` | 当日复盘 HTML 报告 |
| `GET /api/restart` | 无缝重启服务（改代码后用） |

看板顶部有**操作按钮栏**，对应上面四个手动操作，点一下即可，无需记 URL。

## 一天的使用流程

1. **开盘（9:25）**：打开看板。系统自动苏醒开始扫描。
2. **盘中**：盯两个地方——
   - **「每日候选股」卡**：按涨停概率排序的 Top10，带概率条、置信度、可读信号（如"高开+4.5% · 1分钟收复竞价价 · 放量脉冲×8"）。
   - **「报警时间线」卡**：只有双确认的票才出现，出现即**页签标题闪动**提醒。
3. **收盘后**：系统自动生成复盘报告（命中率/涨停率/平均涨幅/最大浮盈/最大回撤/校准误差/误判漏报），并自动迭代模型权重。
